# TXT 阅读网站 MVP 技术方案

依据：[产品设计文档](product-design.md)。本方案确定实现方向，不包含完整接口定义或逐项开发任务。

## 1. 技术选型

采用纯前端单页网站，所有书籍处理和数据保存均在浏览器完成，不建设业务后端。

| 部分 | 选择 | 说明 |
| --- | --- | --- |
| 界面 | React + TypeScript | 实现书架、阅读页和设置面板，使用类型约束数据结构。 |
| 构建 | Vite + npm | 本地开发和生产构建，提交依赖锁文件保证安装可复现。 |
| 样式 | CSS Modules + CSS 变量 | 控制阅读排版、主题和响应式布局。 |
| 存储 | IndexedDB + Dexie | 异步保存书籍、正文块、进度和设置。 |
| 长文显示 | TanStack Virtual | 按文本块虚拟滚动，支持动态高度测量。 |
| 测试 | Vitest + React Testing Library + Playwright | 覆盖文本处理、组件交互及真实浏览器完整流程。 |

项目初始化时选择相互兼容的稳定版本并锁定。不引入全局状态库或大型 UI 组件库；界面状态使用 React hooks，持久数据通过存储模块访问。

## 2. 模块划分

| 模块 | 职责 |
| --- | --- |
| 书架 | 导入入口、最近阅读排序、进度展示和移除书籍。 |
| 导入处理 | 校验文件、解码、规范化换行、切分正文块，返回可保存的数据。 |
| 阅读器 | 虚拟滚动、正文显示、定位当前阅读位置和恢复进度。 |
| 阅读设置 | 字号、行距和主题，更新排版并保存偏好。 |
| 本地存储 | 统一封装导入、查询、更新与删除事务，并向界面返回明确错误。 |

建议源码分别放在 src/features/library、src/features/import、src/features/reader、src/features/settings 和 src/storage 下。文本解码与定位算法使用独立函数，便于测试。

页面采用哈希地址区分书架与书籍，例如 #/ 和 #/read/<bookId>，支持刷新、浏览器前进和后退；书籍不存在时返回书架并提示。

## 3. 数据保存

| 数据 | 主要字段 |
| --- | --- |
| 书籍 | id、文件名、编码、文件字节数、正文总长度、导入时间、最近阅读时间。 |
| 正文块 | bookId、块序号、全书起始偏移、文本内容；以书籍和块序号组成唯一键。 |
| 阅读进度 | bookId、正文偏移、更新时间、是否到达末尾。 |
| 全局设置 | 字号、行距、主题。 |

正文偏移统一指规范化文本的 UTF-16 索引，与 JavaScript 字符串和 DOM 文本偏移一致，定位和分块不切断代理对。

书籍元信息与正文分开读取，进入书架不加载整本书。导入在同一事务内写入元信息、正文及初始进度，全部成功后才显示导入成功；移除时以事务删除相关数据，保留用户原始文件。

首版允许同名文件作为不同书籍导入，每次生成独立 ID，不覆盖既有阅读记录。存储结构使用版本号管理，后续升级通过迁移保留已有数据。

## 4. TXT 导入与显示

1. 校验扩展名（不区分大小写）、空文件和体积；首版建议单文件上限 20 MiB，作为实现与测试边界。
2. 读取字节，使用 TextDecoder 优先按 UTF-8 严格解码，失败后尝试 GBK 严格解码；带 UTF-8 BOM 的文件按 UTF-8 处理。其他 BOM 或两种解码均失败时提示不支持。
3. 自动判断存在歧义，不能保证识别所有编码。导入预览允许在 UTF-8 与 GBK 间手动切换，确认文字正常后保存；纯空白文本拒绝导入。
4. 统一换行为 LF，保留空行、段落及缩进。按约 2,000 个 UTF-16 单元切块，优先选择附近换行；无换行的超长文本也分块。块边界不添加原文没有的段落间距。
5. 解码和分块放入 Web Worker，避免较大文件处理阻塞界面。正文作为纯文本渲染，不把书籍内容当作 HTML 执行。

TextDecoder 提供 UTF-8、GBK 等解码能力，可在 Worker 使用；具体判断流程是本项目的策略。[MDN 文档](https://developer.mozilla.org/en-US/docs/Web/API/TextDecoder)

## 5. 长文阅读与进度恢复

仅渲染当前视口附近的正文块，通过动态高度测量修正滚动区域；每次打开只读取附近正文块，滚动时预取并限制缓存。分块仅用于渲染，不生成目录或章节。[TanStack Virtual 文档](https://tanstack.com/virtual/latest/docs/api/virtualizer)

阅读位置以视口顶部附近的可见文字为锚点，保存对应的全书正文偏移，不使用全书滚动百分比作为恢复依据。阅读进度百分比由正文偏移和总长度计算，到达末尾时显示 100%。

恢复时先查找目标正文块并滚动到附近，待块完成测量后，用 DOM Range 定位文字，再校正滚动位置。修改字号、行距或窗口宽度前捕获文字锚点，重新排版后恢复；恢复期间暂停进度写入，避免临时位置覆盖原记录。

滚动期间最多每 500 ms 保存一次，并在滚动停止时补存；主动返回书架时等待保存完成。页面隐藏时尽力补存，但不依赖关闭页面时的异步写入。异常退出可能丢失最后一次尚未完成的写入。

写入失败时显示“进度未保存”并提供重试，不报告成功。多个页面同时打开时，每本书采用最后一次成功保存的进度；首版不设计跨页面协作。

## 6. 浏览器与部署

首版优先验证桌面 Chrome、Edge，并以 Playwright 的 Chromium、Firefox、WebKit 覆盖核心流程；手机窄屏提供可用的响应式布局，真实移动设备体验另行验收。

执行 Vite 生产构建生成 dist，通过 HTTPS 静态托管发布。使用稳定域名，书籍数据属于同一浏览器的同一来源，换域名不会自动迁移。构建方式参考 [Vite 部署文档](https://vite.dev/guide/static-deploy)。

浏览器本地存储可能受容量限制或被清理，不能视为永久备份。捕获数据库不可用和容量不足错误，保存失败时保留可重试的界面状态；不自动删除其他书籍。[浏览器存储说明](https://developer.mozilla.org/en-US/docs/Web/API/Storage_API/Storage_quotas_and_eviction_criteria)

首版不做 Service Worker 或 PWA，因此本地保存书籍不代表断网后一定能重新打开网站。账号、云同步、其他文件格式仍不在本次范围内。

## 7. 测试与交付

以下是后续实现必须覆盖的测试计划，目前仓库只有文档，尚无应用测试可执行。

| 层级 | 必须覆盖 |
| --- | --- |
| 文本单元测试 | UTF-8、BOM、GBK、乱码回退、手动编码选择、空白文件、20 MiB 边界、换行与分块重组一致、代理对安全。 |
| 存储集成测试 | 导入事务失败不留半本书、同名书独立、单书删除不影响其他书、进度独立、设置保存、容量及写入失败。可用 fake-indexeddb 辅助，并在真实浏览器复验。 |
| 组件测试 | 导入状态与错误提示、书架排序、阅读设置、保存失败后的重试入口。 |
| 浏览器测试 | 导入→阅读→改设置→刷新→恢复；关闭后用同一持久浏览器配置重新打开；改变字号与视口后锚点仍可见；移除记录不修改上传的原始文件；正文中的 HTML 仅显示为文本。 |
| 长文验证 | 使用自生成的 1、5、20 MiB 文件，包括无换行文本，覆盖首、中、末位置恢复及连续滚动。记录测试设备与浏览器、加载耗时和性能轨迹，确认无持续卡顿且 DOM 节点数量不随全文长度增长。 |

计划提供 lint、typecheck、test、test:e2e、build 五项 npm 检查脚本。相关改动更新测试，交付前全部通过并完成阅读页视觉检查；每次完成改动按 AGENTS.md 创建对应 commit。

测试工具参考：[Vitest](https://vitest.dev/guide/)、[Playwright](https://playwright.dev/docs/running-tests)。

## 8. 实现顺序

1. 搭建工程和测试基础，完成 TXT 导入、本地保存、书架和基础阅读闭环。
2. 完成虚拟滚动、文字锚点恢复、阅读设置与保存失败处理，优先验证长文本和重新排版。
3. 完善响应式布局、异常场景与浏览器验证，构建后再安排网站发布。

本次仅交付技术方案，不创建应用工程或部署网站。
